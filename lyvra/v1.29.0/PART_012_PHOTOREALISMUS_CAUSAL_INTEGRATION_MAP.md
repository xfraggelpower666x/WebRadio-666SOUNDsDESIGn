## Required inbound links

### Request and intent router
Routes CGI, game-render, 3D and synthetic-to-real requests to CGI_TO_PHOTOREAL_RECONSTRUCTION. Routes ordinary photographic enhancement only when explicitly requested.

### Reference authority
The uploaded reference image remains the canonical visual source for subjects, identity, proportions, tattoos, clothing, hair, pose, composition and protected objects unless the user explicitly authorizes changes.

### Original Meaning and Identity Locks
Valid identity protection remains active as a concise contract. It is not expanded into repeated prompt paragraphs. Protected characteristics are evaluated before routing and after output.

### Latest Active Development State Gate
The loader must resolve v1.9.0 as the only valid photorealism engine. Any pointer to the removed framework is invalid and must fail closed.

### Transformation Director
The Character Transformation Director determines what may be reconstructed and what must remain visually stable. It may rebuild rendering, skin, hair, materials, light, water, reflections and depth without changing protected identity.

## Required internal links

- HOST_TURN_EXECUTOR receives the classified request and selected runtime profile.
- CANONICAL_RESOLVER resolves identity, composition and user-preservation requirements.
- PROMPT_COMPILER emits no more than four creative prompt blocks.
- CREATIVE_RUNTIME_PROFILES supplies CGI_TO_PHOTOREAL_RECONSTRUCTION behavior.
- HOST_RESULT_EXECUTOR receives generated output and validation results.
- VISUAL_QA_ENGINE checks photorealism quality, identity drift, composition drift, material realism and unauthorized additions.

## Required outbound links

### Visual QA and repair
A failed result does not reactivate the former framework. Failure is classified by responsible cause:
- identity drift → identity validation or resolver repair,
- CGI residue → runtime profile or reconstruction prompt repair,
- material failure → material instruction repair,
- composition drift → canonical resolver repair,
- overconstraint or blocked transformation → prompt compiler repair.

### Experience and decision knowledge
Every validated result and failed result becomes audit evidence. Repeated outcomes may update decision confidence and routing logic, but cannot silently restore deleted legacy behavior.

### Storage and recovery
GitHub, Canonical and PC-Recovery packages must include PART 011, PART 012 and the verified v1.9.0 source identity. Recovery loads the causal map after the replacement declaration.

## Deleted connections

The following links must not exist:
- routing to the former photorealism engine,
- fallback from v1.9.0 to the former engine,
- prompt stacking of former identity or anatomy guards,
- compatibility aliases that silently load the former engine,
- recovery manifests that identify the former engine as valid,
- self-healing behavior that reconstructs deleted legacy prompt blocks.

## Causal compatibility rule

A valid prior connection is retained when it governs identity, intent, routing, audit, storage, recovery, failure analysis or system-state control. A prior connection is removed when it exists only to execute, preserve or restore the faulty photorealism logic.
